# Enable the integrated demo

The deployed site serves `/participate/`. `/api/status` reports configuration availability, not provider health. If required backend variables are absent, participation shows a setup message and mutation endpoints return `503 SETUP_REQUIRED`. Do not enable funding until both providers are verified.

1. In the existing Vercel project, configure server-only values from `.env.example`: Tiger `DATABASE_URL`, `PUBLIC_ORIGIN` matching the deployed origin, distinct authentication secret and email hash pepper, campus email domains, Gemini key/model, and email delivery. `DEMO_MODE=true` permits the documented campus-domain-only shortcut and DRAFT valuation model; it does not prove email ownership. Never place provider secrets in `NEXT_PUBLIC_*` variables.
2. With a private operator environment and owner migration URL, run `npm ci` in `backend`, then check `npm run db:status`. On a fresh database, apply 0001/0002, load the versioned model seed, then apply 0003/0004: the upstream 0003 activation requires that seed already exist. On an existing seeded database, run `npm run db:migrate`. Migration 0004 extends the existing schema and preserves historical intents. Load the versioned valuation seed with `npm run -s db:model-sql` using the existing database operator workflow. The app role must retain the grants from all migrations. No remote migration has been run in this implementation session.
3. Build the Solana program: Anchor 0.32.1, `cargo test --manifest-path chain/Cargo.toml`, and `cargo-build-sbf --manifest-path chain/programs/prospecto/Cargo.toml`. A local toolchain using Solana 4.3.0 built the program successfully. The committed address is a **local build placeholder**. Before Devnet deployment, synchronize `declare_id!`, `chain/Anchor.toml`, and `backend/idl/prospecto.json` to the deployed program address; rebuild the SBF and IDL. Deploy using the operator's own wallet. The agent has not deployed or signed a Devnet transaction.
4. Create a six-decimal Token-2022 mock payment mint, with no extensions or freeze authority and the configured relayer as mint authority. Initialize the protocol with the program upgrade authority and relayer. The initialization instruction rejects a different upgrade authority. Set Devnet RPC, actual program ID, payment mint, and server relayer configuration in Vercel. The committed compiled IDL is bundled; after deploying to a different address, regenerate it and redeploy the backend. Do not put a wallet private key in chat or source control.
5. Verify Nessie semantics in an isolated sandbox using the read-only probe. A candidate profile describes observed response envelopes and statuses; it is not evidence by itself. Run `npm run nessie:probe -- baseline candidate.json baseline.json payerAccount treasuryAccount`. Create exactly one tagged mock transfer in the provider sandbox, save its 201 response privately as `{ "httpStatus": 201, "body": ... }`, then run `npm run nessie:probe -- verify candidate.json baseline.json transferId description wholeDollars create-response.json verified-profile.json`. Verification requires one matching successful transfer, both histories, and both balance changes. No probe command sends a transfer. Keep definitive-no-effect HTTP statuses empty unless separately verified.
6. Provision only synthetic participant accounts with an initial 1,000 simulated dollars and a fresh treasury with zero. Create a private manifest following `backend/examples/bank-accounts.example.json`. Register with `npm run register:bank-fixtures -- private-manifest.json`. Registration reads provider ownership and initial balances, binds existing Prospecto identities, and replays without resetting balances. Use a fresh generation for a reset. Store the verified profile as server-only `NESSIE_PROFILE` JSON on Vercel (a local file override is available), with the key, matching origin, treasury ID, and generation.
7. Enable `PURCHASES_ENABLED=true` only after finalized account checks; enable `NESSIE_ENABLED=true` only after the probe and fixture registration. Redeploy. Sign in, connect Phantom and prove ownership, fund the demo wallet, and wait for `COMPLETED` with a finalized funding receipt. A founder publishes a project, signs its receipt-mint transaction, freezes terms, signs round opening, and shares its round ID. A different campus identity loads that round, previews the commitment, reviews simulation, signs, and follows status. Refresh the portfolio after close to trigger bounded allocation/refund reconciliation.

## Recovery and verification

A lost funding response is recovered by the same request key. GET polls may reconcile existing provider writes; only an authorized funding/resume POST can dispatch a new bank write. Uncertain provider writes never cause a blind second POST. Browser session storage retains identity-scoped intent IDs and request keys, never cookies or private keys. Submission accepts only the exact persisted transaction message. Unknown chain outcomes retain their signature; no UI action automatically signs again.

The indexer records finalized events and metrics in one transaction, resolves native foreign keys before immutable insertion, and deduplicates replay. Missing database mappings retain the backfill cursor for operator recovery. Settlement mirrors are also refreshed from validated finalized program accounts on demand. There is no persistent worker: traffic or explicit refresh must trigger reconciliation, including after round close. Large backfills require an operator run; per-request limits retain the cursor if exceeded.

Run backend typecheck and tests, frontend lint and build, Rust arithmetic tests, and SBF execution tests. `RUN_CHAIN_TESTS=true npm test -- tests/chain` in backend requires the compiled artifact and fails if it is absent. The compiled tests exercise non-transferability, funding replay/mismatch, wrong relayer/proof/accounts, subscription failure without debit, early finalization, cancellation, fee conservation, and rollback across allocation/refund instructions. Mock provider and local VM tests do not establish live Nessie or Devnet success. A real browser happy path still requires the configuration above.

Dependency audit identified advisories in the legacy Anchor/web3/SPL dependency tree and frontend lint tooling. The compatible PostCSS patch is pinned. Remaining legacy issues require a separately tested SDK migration; the backend accepts bounded validated transaction/account inputs and never parses user TOML. This is a Devnet hackathon implementation, with purchases disabled by default.

Rollback: disable purchases and Nessie flags and redeploy. Preserve migration 0004 and all historical evidence; reconcile already dispatched intents before resetting a demo generation. Rolling back the frontend does not undo finalized chain instructions or provider transfers.

Deployment verification for this integration: the merged backend suite passed 212 tests (4 existing tests skipped); the final purchase/SBF suite passed 98 tests; frontend lint/static export passed; Rust passed 6 tests including the shared documented goldens; SBF compilation passed. The new Vercel project's provider environment remains empty. Git-triggered Vercel deployments require the commit author email to match the connected GitHub account; use that account's verified address or GitHub noreply address for deployment commits.

Vercel compatibility: the API builder uses TypeScript 5.9.3 with development type declarations installed during the build. The legacy RPC websocket CommonJS entry requires a CommonJS-compatible UUID package; a scoped override pins UUID 11.1.1 (the last supported CommonJS series), because UUID 12+ removed that format. See the [upstream UUID change](https://github.com/uuidjs/uuid/releases/tag/v12.0.0).
